# v0.0.10 更新说明

## 发布摘要

`v0.0.10` 完成 TAR/TAR.Zstandard 的第一阶段 `archive-core` 迁移。Android 继续保留 SAF、缓存、权限和系统 chooser 适配，归档格式处理、路径安全、限制、取消和临时 staging 由 Kotlin/JVM 核心负责。

版本元数据：`versionCode 12`、`versionName 0.0.10`。

## 具体变更

### TAR 核心迁移

- 新增 `TarArchiveCore` 和 `TarCompression`，支持 TAR 与 TAR.Zstandard 的列表、创建、事务式解压、选定条目解压、受限单条目读取和流式条目复制。
- 使用 Apache Commons Compress 处理 TAR 容器，使用 `zstd-jni` 处理 Zstandard 流；两项依赖已加入 `archive-core`，Android 与 JVM 测试共享同一实现。
- 创建归档先写入同目录随机 `.part` 文件，成功后再替换目标；取消、异常和输出冲突不会留下未完成归档。

### 安全与边界

- 拒绝绝对路径、Windows 盘符路径、路径穿越、NUL、重复规范化路径以及文件/目录父子冲突。
- 拒绝 TAR 符号链接和其他特殊条目，解压 staging 与目标路径均拒绝符号链接穿透。
- 统一检查最大条目数、最大展开体积、单条目读取上限和取消状态；解压完成边界校验后才提交 staging 内容。
- 统一支持 `REPLACE`、`SKIP`、`RENAME` 覆盖策略，并保持进度回调和失败清理行为。

### Android 接入

- TAR/TAR.Zstandard 创建改为从 Android staging 根目录调用 `TarArchiveCore`。
- TAR/TAR.Zstandard 列表、解压、预览和外部打开改为调用核心；SAF URI 暂存、`DocumentFile` 目标写入、系统 chooser 和 URI 权限仍留在 Android 适配层。
- 启动清理覆盖 ZIP/TAR 核心解压 staging，避免进程被杀死后遗留缓存目录。
- 保留 `v0.0.9-fix2` 的 SAF 单文件修复：`/tree/...` 使用 `fromTreeUri()`，`/document/...` 使用 `fromSingleUri()` 和 `ContentResolver.openInputStream()`，不新增 `MANAGE_EXTERNAL_STORAGE`。

## 测试与发布门禁

- 新增 Unicode 文件名、空目录、空文件、路径穿越、展开体积上限、取消清理、单条目读取上限和 TAR.Zstandard 闭环测试。
- JVM 验证命令：`gradle --no-daemon --max-workers=1 :archive-core:test`。
- Android/Release 验证命令：`gradle --no-daemon --max-workers=1 :archive-core:test test lintRelease`。
- 签名构建命令：`gradle --no-daemon --max-workers=1 assembleRelease`。
- Release workflow 检查 `arm64-v8a`、`armeabi-v7a`、`x86` 和 `universal` 四种 APK 的签名证书一致性，并上传 APK、`SHA256SUMS.txt`、`mapping.txt` 和 `RELEASE_METADATA.md`。

## 不在本版本范围内

- RAR/RAR5、7z 和独立 Zstandard 尚未迁入 `archive-core`；RAR 创建仍不做。
- ZIP、TAR、Zstandard 密码加密、桌面 GUI/TUI/CLI、Windows/Linux/macOS 原生打包和桌面云端功能仍未实现或验收。
- 本版本不宣称任何桌面平台已支持；桌面 MVP 仍需独立的 CLI/TUI/GUI、原生 CI、安装包和端到端验收。
