# v0.0.9-fix1 更新说明

## 本次变更

- 独立 Kotlin/JVM `archive-core` 增强 ZIP 创建、列表、事务式解压和单条目受限读取边界。
- ZIP 创建明确支持 Deflate 和仅存储模式；仅存储条目写入正确的 CRC-32 元数据。
- ZIP 核心增加损坏归档、异常条目大小、重复规范化路径、路径冲突和展开上限回归测试。
- Android ZIP 列表、创建、解压和受限预览通过临时本地文件调用 `archive-core`，SAF 仍由 Android 适配层负责。
- 核心错误码显式映射到 Android 领域错误，进度回调使用合并通道避免大文件操作积压内存。

## 限制

- RAR/RAR5、7z、TAR、Zstandard 和 TAR+Zstandard 尚未迁移到 `archive-core`。
- RAR 创建、ZIP 自研加密、办公套件内置、云盘 SDK 和桌面 GUI/TUI/CLI 不在本版本完成条件内。
- 当前不宣称 Windows、Linux 或 macOS 桌面支持。

## 验证

Release workflow 必须通过以下检查后才可视为发布完成：

```sh
gradle --no-daemon --max-workers=1 :archive-core:test test lintRelease
gradle --no-daemon --max-workers=1 assembleRelease
```

发布产物应同时包含四种 ABI APK、`mapping.txt`、`SHA256SUMS.txt`、签名证书指纹和 `RELEASE_METADATA.md`。
