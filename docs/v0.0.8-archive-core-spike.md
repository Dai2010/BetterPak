# v0.0.8 `archive-core` JVM Spike

本文记录 v0.0.9 发布前的阶段快照；后续未发布的 ZIP Android 适配进展见 `docs/v0.0.10-archive-core-migration.md`。

本轮按 `NEXT_PLAN.md` 的第一阶段执行：先建立不携带 Android `Context`、`Uri` 或 `DocumentFile` 的 Kotlin/JVM 归档边界，暂不把 Android 归档实现整体重写。

## 已实现

- 新增 `:archive-core` Kotlin/JVM 模块，使用 JDK 17，Android `:app` 已声明模块依赖作为后续适配接缝。
- `ZipArchiveCore` 支持 ZIP 列表、创建、完整解压、选定条目解压和单条目受限读取。
- `ArchivePath` 拒绝绝对路径、Windows 盘符路径、路径穿越、NUL 和空条目；重复规范化路径以及文件/目录路径冲突会失败。
- 创建输出先写入同目录随机 `.part` 文件，成功后再移动到目标；取消或异常会删除临时输出。
- 解压先完整校验条目路径、条目数量和声明体积，再写入隔离 staging 目录；读取过程继续执行展开体积限制，失败或取消会清理 staging，不把未完成文件提交到目标目录。
- 输入和目标路径的符号链接、非普通文件、输出覆盖输入、选择路径非法、覆盖策略、进度回调和取消均有明确边界；解压不会跟随目标目录中的符号链接。
- 单条目读取也执行受限流式读取，支持取消和进度回调；已知条目大小超过读取上限时会在打开数据流前失败。
- 测试覆盖 Unicode 名称、空文件、空目录、路径穿越、选择解压、读取限制、读取取消/进度、重复规范化路径、输出父路径冲突、符号链接、取消清理和 ZIP 创建/列表/解压闭环。

## 暂未完成

- `ArchiveRepository` 仍是 Android 实现，尚未改为调用 `ZipArchiveCore`；这一步需要先设计 SAF `Uri` 到 JVM `Path`/source/sink 的适配，不能只替换类型名。
- RAR/RAR5、7z、TAR、Zstandard、预览策略、错误类型映射和任务执行恢复尚未迁移到核心模块。
- 尚未增加 GUI、TUI、CLI、桌面文件选择器、原生打包或云端桌面 OAuth；也没有宣称任何桌面平台已支持。
- 当前 Termux 没有 Java、Gradle 或 Android SDK，无法在本机执行 Gradle 测试或 Android 构建。
