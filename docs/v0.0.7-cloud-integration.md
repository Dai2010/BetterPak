# v0.0.7 云端接入记录

## 已实现的基础层

- `CloudProvider`、`CloudAccount`、`CloudItem`、分页、传输进度和统一错误模型位于 `domain`，归档引擎不依赖厂商 API。
- `OneDriveProvider` 使用 Microsoft Graph v1.0，提供目录分页、文件下载、小文件上传和 Graph upload session 分片上传。
- `GoogleDriveProvider` 使用 Google Drive API v3，提供目录分页、文件下载和 resumable upload；不使用已废弃的 Android Drive API。
- 共享 HTTP 层统一 HTTPS API 请求、超时、有限重试、取消检查、响应错误分类和下载 `.part` 文件原子替换。
- OAuth 工具只生成授权码 + PKCE 请求，不保存 client secret；Token 使用 Android Keystore 的 AES-GCM 加密后存入独立凭据存储。
- 访问令牌过期时，`RefreshingCloudTokenProvider` 使用保存的 refresh token 获取新令牌；Token 不进入 `ArchiveTaskStore`、通知、日志或崩溃信息。

## 权限与配置边界

- OneDrive 首版应使用单独注册的移动应用和个人账号测试配置；上传需要写权限，读取/下载场景不应额外申请写权限。
- Google Drive 默认评估 `drive.file`；读取用户已有归档所需的权限范围、OAuth 同意和审核要求必须在真实测试账号上确认，不能默认申请整个云盘读写。
- client ID、回调地址和权限范围通过应用配置注入，不写入 Token 存储、仓库或任务记录；客户端不保存 client secret。
- 目前 provider 是可调用的 data 层能力，尚未接入 Compose 登录/目录选择 UI，也未在本机宣称真实账号互操作通过。
