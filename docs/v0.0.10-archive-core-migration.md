# v0.0.10 `archive-core` 核心迁移工作记录

本记录对应 `NEXT_PLAN.md` 中 `v0.0.10` 的核心迁移与发布记录。版本元数据为 `versionCode 12`、`versionName 0.0.10`；本版本不宣称任何桌面平台已支持。

## 已完成

- `archive-core` 的 ZIP 创建增加 Deflate 和仅存储两种明确模式；仅存储条目写入正确的大小、压缩大小和 CRC-32。
- ZIP 列表在核心层检查条目数量、规范化路径、重复路径、文件/目录父子冲突和异常条目大小；损坏 ZIP 的 I/O 错误映射为 `CORRUPT_ARCHIVE`，而不是权限错误。
- 单条目读取同时服从调用方读取上限和核心展开上限，继续使用流式读取、取消检查和进度回调。
- Android ZIP 列表、创建、解压和受限预览通过临时本地文件调用 `ZipArchiveCore`；`ContentResolver`、`DocumentFile`、SAF 权限和最终输出替换仍留在 Android 适配层。
- Android 与核心错误码之间增加显式映射；核心进度通过合并通道转发，避免大文件进度回调积压内存。
- ZIP 解压先在核心 staging 目录完成路径、数量、体积和符号链接边界检查，再逐项复制到 SAF 目标并沿用 Android 覆盖策略。
- `archive-core` 新增 `TarArchiveCore`，覆盖 TAR 与 TAR.Zstandard 的列表、创建、事务式解压、选定条目解压和受限单条目读取；输入路径、归档路径、特殊条目、重复条目、路径冲突、体积、取消和临时文件清理由 JVM 核心统一处理。
- Android TAR/TAR.Zstandard 的创建、列表、解压、预览和外部打开改为调用 `TarArchiveCore`；SAF URI 暂存、目标 DocumentFile 写入和 chooser 仍留在 Android 适配层。
- TAR 核心测试增加 Unicode/空目录/空文件、TAR.Zstandard 闭环、路径穿越、展开体积上限、取消清理和单条目读取上限覆盖。

## 尚未完成

- RAR/RAR5、7z 和独立 Zstandard 尚未迁移到 `archive-core`；RAR 创建仍不做。
- `ArchiveTaskStore`/`ArchiveTaskViewModel` 的真实执行恢复、WorkManager 评估和进程杀死后的重放仍未完成。
- Android 真机的 SAF 权限撤销、空间不足、取消清理、外部 chooser 和不同 DocumentProvider 尚未由本次改动替代验收。
- GUI、TUI、CLI、原生安装包、Windows/Linux/macOS runner 和桌面云端功能仍未实现；桌面支持矩阵保持未验收状态。

## 验证状态

当前 Termux 已使用 Java 17 和 Gradle 完成 `:archive-core:test`；17 个测试中 16 个通过，TAR 核心的 6 个测试中 5 个通过，TAR.Zstandard 测试因 Termux 缺少 `libpthread.so.0` 被环境假设跳过。当前没有 Android SDK，因此 Android 单元测试、Lint 或 APK 构建仍需 CI 或具备 SDK 的开发机运行：

```sh
gradle --no-daemon --max-workers=1 :archive-core:test
gradle --no-daemon --max-workers=1 test lintRelease
```

Android 全量测试、Lint、签名构建和产物检查由 Release workflow 作为发布门禁执行；真机 SAF 和外部 chooser 验收仍需在具备 Android 设备的环境补充记录。
