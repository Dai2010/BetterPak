# v0.0.6 实现记录

## 已实现

- `ArchiveEngine` 作为 UI 与 ZIP、RAR/7z、TAR/Zstandard 实现之间的领域边界，保持现有格式能力矩阵不变。
- `ArchivePath` 校验继续拒绝绝对路径、路径穿越、NUL 和 Windows 风格绝对路径；ZIP、RAR、7z 列表和解压遇到非法路径时失败，不再静默丢弃条目。
- 预览策略独立为领域组件，文本、图片、音频和视频保留受限预览；PDF、办公文档、未知二进制和预览失败会降级为用户选择的解压/外部打开，不自动启动第三方应用。
- 外部打开流程使用受限缓存、`FileProvider`、正确 MIME 类型和 `Intent.createChooser()`；缓存只清理超过生命周期的文件，应用不执行宏、脚本或嵌套归档。
- 任务状态包括待处理、运行中、成功、失败、取消、可重试和进程恢复；创建、完整解压和预览页解压由 ViewModel 观察，持久化记录不包含密码。
- 设置持久化最大条目数、最大展开体积、最大预览大小和覆盖策略；不增加宽泛存储权限，也不引入 WorkManager、RAR 编码器或办公套件依赖。
- Release 版本提升为 `0.0.6`；APK-only workflow 继续构建 `arm64-v8a`、`armeabi-v7a`、`x86` 和 universal APK，并将 `mapping.txt`、SHA-256 和运行元数据归档。

## 验证清单

在具备 Java、Gradle、Android SDK 的 CI 或开发机执行：

```sh
gradle --no-daemon --max-workers=1 test lintRelease
gradle --no-daemon --max-workers=1 assembleRelease
```

需要真机或 Android 文件管理器补验收：

- 通过 `VIEW`/`SEND` 打开 ZIP、RAR/RAR5、7z、TAR、`.zst` 和 `.tar.zst`，并验证 URI 权限撤销后的错误提示。
- 验证办公文档的 chooser、没有外部处理器、用户取消、外部应用拒绝打开、返回 BetterPak 和缓存生命周期。
- 验证旋转、后台切换、进程重启、取消、重试、输出冲突、空间不足和残留 `.part` 文件。
- 使用固定哈希样本回归路径穿越、TAR 软链接/硬链接/设备文件/FIFO、损坏流、错误密码、超限条目和超限展开。

当前 Termux 环境没有 Java、Gradle 或 Android SDK，因此本地不能替代上述 Android 构建、单元测试和真机验收；该限制与 `docs/format-sample-acceptance.md` 的记录一致。

## 安全边界

- RAR 只读/解压，不提供创建入口；ZIP 自研加密、AAB、云盘 SDK 和内置 LibreOffice 不属于 v0.0.6 完成条件。
- 密码只作为当前协程调用的内存参数传递，不写入 `ArchiveTaskStore`、DataStore、通知或日志。
- 外部应用接管文件后的行为不受 BetterPak 控制，用户必须在 chooser 中明确选择处理器。
