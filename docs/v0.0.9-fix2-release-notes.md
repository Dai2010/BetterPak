# v0.0.9-fix2 更新说明

## 本次变更

- 修复 Android SAF 单文件 `/document/...` URI 在创建归档时被错误传给 `DocumentFile.fromTreeUri()` 导致 `Invalid URI` 的问题。
- 使用 `DocumentsContract.isTreeUri()` 分流：目录树 URI 使用 `fromTreeUri()` 并保持递归暂存，普通文件 URI 使用 `fromSingleUri()` 和 `ContentResolver.openInputStream()` 暂存到应用缓存目录。
- ZIP、7z、TAR 和 TAR+Zstandard 共用同一套输入暂存修复；输出写入、进度、取消和失败后的临时目录清理逻辑保持不变。
- 将权限撤销、无效 URI、空文档、非文件对象、目录子项读取失败和临时目录创建失败转换为类型化的中文可操作提示。
- 不新增 `MANAGE_EXTERNAL_STORAGE`，不把 `content://` URI 猜测转换为共享存储路径，也不让 `archive-core` 直接处理 Android URI。
- 增加 `Invalid URI` 和权限撤销错误提示回归测试，版本号递增为 `versionCode 11`、`versionName 0.0.9-fix2`。

## 发布 workflow 的具体变更点

- 手动触发默认 tag 改为 `v0.0.9-fix2`，并要求发布请求包含本次变更摘要。
- workflow 在构建前校验 tag 与 `versionName` 一致，执行 `:archive-core:test`、`test` 和 `lintRelease`。
- workflow 继续构建并检查 `arm64-v8a`、`armeabi-v7a`、`x86` 和 `universal` 四种签名 APK，确认四个 APK 的证书指纹一致。
- `RELEASE_METADATA.md` 和 GitHub Release body 明确记录 URI 分流、目录兼容、中文错误提示、无全盘权限和测试命令。
- Release 资产继续包含 APK、`SHA256SUMS.txt`、`mapping.txt` 和 `RELEASE_METADATA.md`。

## 验证

自动验证命令：

```sh
gradle --no-daemon --max-workers=1 :archive-core:test test lintRelease
gradle --no-daemon --max-workers=1 assembleRelease
```

真机发布前还需要完成 Downloads 单文件、目录选择、重启后权限、输出到新建目录，以及 ZIP、7z、TAR、TAR.Zstandard 的创建和重新读取验收。未完成真机验收前，不将该版本标记为最终发布完成。

## 限制

- RAR 创建、ZIP 自研加密、内置办公套件、云盘 provider 和桌面 GUI/TUI/CLI 不在本版本范围内。
- 当前不宣称 Windows、Linux 或 macOS 桌面支持。
